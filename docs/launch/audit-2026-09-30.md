# Reliability, user-flow and resource audit — 2026-09-30

Scope: extension setup/capture/processing/history, helper audio/provider/recovery,
webapp auth/tenant writes/uploads/jobs/cleanup/billing, and release automation.
Read-only finding sweeps preceded the changes. No CodeGraph index existed in
the checkout, so normal source tools were used. The initial worktree was clean.

## Confirmed issues repaired

| Priority | Trigger and impact | Repair |
| --- | --- | --- |
| P1 | Two workspaces register the same new meeting ID concurrently; default transaction isolation permits cross-tenant overwrite | Transaction-scoped advisory lock before ownership read |
| P1 | Concurrent equal-byte chunk retries use a shared storage key; a losing request deletes committed audio | Each request stages its own object; only its uncommitted object is removed |
| P1 | Hosted Meet exceeds 10,000 capture frames (~42 minutes with two channels); manifest rejected | Stream deterministic 4 MiB per-channel upload packing |
| P1 | Provider remains offline through Stop; saved streaming gap never transcribed | Queue durable bounded ranges and defer summary until retry recovery |
| P1 | Retry after upload-layout upgrade can revive a job pointing at expired legacy audio | Failed jobs validate meeting identity and use the replacement completed upload |
| P2 | Ambiguous service-worker reply causes re-delivery of already stored audio | Stable sender chunk identity, atomically deduplicated in IndexedDB |
| P2 | Slow live socket accumulates unbounded PCM; stalled helper providers retain call audio in queue | Bound WebSocket backlog; helper queues hold disk ranges |
| P2 | Reconnect loads an entire provider outage into one allocation/request | Bounded 30-second catch-up ranges |
| P2 | A start on another Meet tab returns the active meeting ID, falsely showing recording | Require active recording's tab to match |
| P2 | Open detail page stays processing after error or misses later Drive completion | Listen for outcome/state/Drive events; show Retry |
| P2 | Popup hides helperless live captions and desktop→Meet action stays on desktop surface | Correct source/status handling and open Meet explicitly |
| P2 | Old provider-key test response validates keys edited while request was running | Revision guard for success, denial and failure responses |
| P2 | Audio allowance exhausted while meeting-count warning still looks healthy | Separate quota warnings and correct billing wording |
| P2 | Cleanup revisits only first five object pages; deletion fans out to 10,000 requests | Continue sweep pages; bounded cleanup/deletion work |
| P2 | Global workers query indexes whose leading key is workspace ID | Global job-state/age and upload-expiry indexes |
| P2 | Release checks trigger SHA but checkout follows newer main | Checkout checked SHA, skip superseded run, atomic branch/tag push |

Resource changes preserve local-first raw audio, separate channels, protected
local BYOK credentials, project-owned managed secrets, authenticated workspace
access, Native Messaging and the committed extension key. No new localhost
capture port, virtual driver, or permanent managed audio library was added.

  live captions connecting→available→fallback retains transcript. Dark 360px
  popup has no horizontal overflow or page errors. Screenshots are under

  errors or overflow. Owned server/database were cleaned up afterward.
